### 通知计时方案

在可调整全局设置的演示环境中，可将“临近截止时提醒”提前量临时设为 1 分钟，C 的截止设为开始演示后约 7 分钟，使计划触发落在约第 6 分钟；实际创建后应核对显示的截止和计划条件。每日汇总和危险期若无需本轮展示，可按事先记录单独控制，避免多个原因干扰观察。若要展示同刻合并，再独立使用危险期和临近提醒同刻的专用样本，不混入首次路由验证。

该计划不是精确送达承诺。设备若在省电或近似调度状态，应如实记录；不要更改系统时钟来强制触发。通知等待时间可提前安排，现场流程超过 8 分钟时优先保留数据与状态操作的完整说明，再单独展示通知证据。

### 固定 tag 没有输出时

本轮实际遇到 `persist.log.tag=S`，原本的 App 错误与同 tag shell 采集探针均为零行。只临时提高单个非持久 tag 到 W 后，才采到 App 的 `open_source／security_denied` 与受控 `decode_image／validation`；该诊断阶段结束后已恢复原空值，全局持久 S 未改。后续真实重启后收尾曾观测全局值为 M，另经授权单次恢复基线 S；机制未知，原始差异与恢复记录见本批证据。这次收尾恢复不是启用诊断的步骤。shell 探针与 App 事件必须分开登记，零行不能直接说明 App 没有失败。

下次先只读记录阈值，并检查命令成功退出；不能把设备离线或 ADB 失败误当作“属性为空”：

```powershell
function Read-AttachmentLogProperty([string] $PropertyName) {
    $propertyOutput = & adb shell getprop $PropertyName
    if ($LASTEXITCODE -ne 0) {
        throw "读取 $PropertyName 失败，停止采集。"
    }
    return ([string]($propertyOutput -join "`n")).Trim()
}

$previousPersistentLogLevel = Read-AttachmentLogProperty 'persist.log.tag'
$previousGlobalLogLevel = Read-AttachmentLogProperty 'log.tag'
$previousPersistentAttachmentLevel = Read-AttachmentLogProperty 'persist.log.tag.DDLSaver.Attachment'
$previousAttachmentTagLevel = Read-AttachmentLogProperty 'log.tag.DDLSaver.Attachment'
[pscustomobject]@{
    PersistentGlobal = $previousPersistentLogLevel
    Global = $previousGlobalLogLevel
    PersistentAttachment = $previousPersistentAttachmentLevel
    Attachment = $previousAttachmentTagLevel
}
```

如确需临时显示该 tag，保留原值并仅调整这个非持久属性；不要为此改变全局日志设置。以下续用上面的只读结果和函数，适用于本轮“原值为空”的情况；若原值不同，应按实际值恢复，不能直接套用空值：

```powershell
if ($previousAttachmentTagLevel -ne '') {
    throw '此示例只适用于已核对原 tag 值为空的情况；请保留并按实际原值恢复。'
}
try {
    adb shell setprop log.tag.DDLSaver.Attachment W
    if ($LASTEXITCODE -ne 0) { throw '设置单 tag 失败。' }
    if ((Read-AttachmentLogProperty 'log.tag.DDLSaver.Attachment') -ne 'W') {
        throw '未确认单 tag 已变为 W，停止采集。'
    }
    adb logcat -v threadtime -s 'DDLSaver.Attachment:W' '*:S'
    if ($LASTEXITCODE -ne 0) { throw '日志采集未正常退出；仍执行恢复。' }
}
finally {
    adb shell "setprop log.tag.DDLSaver.Attachment ''"
    $restoreAttachmentExitCode = $LASTEXITCODE
    $restoredAttachmentLevel = Read-AttachmentLogProperty 'log.tag.DDLSaver.Attachment'
    $restoredPersistentLogLevel = Read-AttachmentLogProperty 'persist.log.tag'
    if ($restoreAttachmentExitCode -ne 0 -or $restoredAttachmentLevel -ne $previousAttachmentTagLevel) {
        throw '未确认单 tag 恢复原值，必须记录并完成恢复。'
    }
    if ($restoredPersistentLogLevel -ne $previousPersistentLogLevel) {
        throw '全局持久日志属性与原值不符，需核对原因。'
    }
    Write-Output '已复读确认：单 tag 恢复原值，全局持久日志属性保持。'
}
```

该步骤不清空设备日志、不固定旧 PID、不收集其他 tag；记录临时设置和恢复后的实际值。日志类别只是本次失败阶段证据，不单独证明授权为何失效或所有来源存在同一问题。

## 4. 收尾与结果归档

1. 回看本轮前缀，逐条确认需要清理的样本；只删除本轮创建的数据。复核原有事项、字段及附件保持。
2. 恢复记录的提醒开关、汇总时刻、提前量、过期策略、角色形象、字号及临时系统设置；确认提醒恢复安排的页面结果。原系统权限是否保留或恢复按本次约定记录。
3. 若创建本轮专用来源／标签，先核对没有非本轮引用，再按产品支持的方式停用；不操作共享分类以伪造完全空库。
4. 将实际步骤、失败与复测、计划／观察时刻、必要截图、版本和哈希补入[执行记录](test-records.md)，逐项更新[测试计划](test-plan.md)。没有执行的行仍保留待测。
5. 由小组核对[项目报告汇编](final-report.md)、独立需求／设计／测试报告及源码一致性，再按老师确认的格式提交。准确日期、时刻、最终模板和演示时长仍需确认。
