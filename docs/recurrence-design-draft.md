# 重复事项设计草稿

状态：2026-11-02 初步设计，尚未接入界面、数据库或提醒。按[扩展需求 PX-03](planning-extension-requirements.md)推进，具体方案与团队审核仍需结合后续实现确定。

现有 `events` 以单个 ID 保存状态与修订；提醒计划按事项 ID、截止时间和修订区分，附件文件路径为唯一私有副本。简单复制事件会与附件所有权、独立状态、提醒去重和系列编辑冲突。

建议采用系列规则与单次实例分离：系列保存原始截止时间、频率和结束条件；实例以系列 ID 与周期序号唯一识别，保存独立的完成、跳过、调整和历史数据。仅展开有限时间窗口，历史与修改过的实例持久保存；扩展窗口、重启和并发写入必须幂等。系列变更影响范围、附件引用和过期实例清理需要在持久化设计中进一步明确，不能让未来重复实例引用可能被另一事项删除的私有附件。

`RecurrenceRules` 实现北京时间下每日、每周、每月的纯计算及有限范围查询：月末以首个日期为锚；结束日期含当天；次数包含首项；窗口结果设置上限。该计算代码不会创建事件或触发通知。之后仍需实现实例物化及单次／系列编辑、跳过与完成、通知重排、表单和详情入口，补齐重启、并发、提醒和 UI 测试，最后再做设备验证。

后续数据层增量将数据库升级至 schema 5，新增系列和周期记录表：以系列 ID 与周期序号作为复合主键；单次关联的事件 ID 唯一，但暂不设事件外键，生命周期与一致性将在事件接入时明确。新增 4→5 显式迁移，只创建新表和索引，旧事项不转换。当前 DAO 提供基础读写和重复周期插入保护；它尚不负责创建事项、同步状态、并发生成、提醒或附件所有权，因此不能视为完整的重复任务功能。

已关联到事件的周期通过现有单项或批量删除操作删除时，同一数据库事务把该周期标记为跳过并断开事件关联，同时沿用现有提醒重建；批量选择失效时事务不改变任何周期。这只覆盖已关联实例的删除，尚未提供系列删除、撤销跳过或周期生成入口，也没有解决附件模板和长期后台生成。

周期计算层新增缺失周期筛选：调用方传入已持久化的全部序号（包含已跳过的序号），计算时不重新生成这些周期。此函数只是无副作用的候选计算，实际插入仍须在数据库事务中依靠复合主键避免并发重复；目前尚无自动调用方。

数据层提供版本化系列模板与有限范围生成：在单个事务中写入系列、生成独立事件与关联并重建提醒；重复调用保留已有及跳过的周期。模板保存标题、描述、速通时间、重要程度、来源、标签和文本字段；旧分类停用后保留原关联。新建及普通事项编辑页面可选择重复频率及结束条件；重复任务不支持图片。提醒协调时补充到当前时刻后 90 天，受通知权限、系统后台和强停限制；单次完成、编辑、删除相互独立。系列级修改／删除保留完成与归档历史；月重复额外记录目标日，短月份不改变后续锚点。极长历史生成与设备条件仍需核查。
