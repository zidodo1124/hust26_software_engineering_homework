## 2. 背景、用户与项目目标

### 2.1 背景与问题

大学生同时面对课程作业、学生工作、家庭、生活与社交事务，截止时间分散在不同来源中。用户容易遗忘事项，或直到临近截止才意识到完成任务所需的时间已经不足。文字、截图、链接等关联材料也容易与待办本身分离。

### 2.2 目标用户与使用角色

第一版面向使用 Android 手机的大学生。应用内只有本机使用者这一业务角色，不设置登录账户、管理员或协作成员。课程小组成员是项目开发参与者，不是应用内权限角色。

### 2.3 产品目标

1. 把不同来源的 DDL 集中管理，让用户能够快速记录并找到事项。
2. 通过角色、气泡卡片、紧急标识和统计，让用户看清当前要处理的事情。
3. 结合截止时间与用户估计的“速通时间”，提示需要开始行动的事项。
4. 利用每日汇总、危险期和临近截止通知，在用户未主动查看列表时提供提醒。
5. 保存描述和截图等上下文，减少再次查找原始消息的成本。

目标是辅助用户规划与记忆；应用不能保证用户一定按时完成任务。

## 4. 主要使用场景

| 场景编号 | 场景 | 用户期望 |
| --- | --- | --- |
| US-01 | 收到一项作业或事务 | 录入标题、截止时间，并按需补充截图、描述、来源和标签 |
| US-02 | 打开应用安排当天事务 | 看见角色、DDL 气泡卡片、今日数量与危险期数量，识别紧急事项 |
| US-03 | 开始处理某项事务 | 打开详情，查看要求和截图，复制描述中的网址等信息 |
| US-04 | 任务要求或时间发生变化 | 修改已有事件，并让界面与后续提醒使用更新后的信息 |
| US-05 | 未主动打开应用 | 收到每日汇总或事件提醒，点击后进入应用查看相关事项 |
| US-06 | 积累了较多过期事项 | 在保留历史信息的默认行为下整理事项，使用批量管理减少重复操作 |
| US-07 | 完成任务或需要重新处理 | 标记完成、停止提醒并进入历史；必要时恢复为未完成 |
| US-08 | 事项较多或存在特殊信息 | 搜索和筛选目标事件，为事项增加地点、联系人、网址等自定义字段 |

| 标题 | 必填 | 识别事项的主要文字；建议去除首尾空白后仍须有内容 |
| 截止时间 | 必填 | 北京时间的日期、小时与分钟；不提供仅选日期的全天事件 |
| 重要程度 | 选填 | 独立于时间紧急度；建议低、中、高三级，默认中 |
| 来源 | 选填 | 例如学习、学生工作、家庭、生活、社交；这些是原文例子，不是已锁定枚举 |
| 标签 | 选填 | 给事件添加便于识别的分类信息；建议来源与标签均支持用户增删改，维护选项时保留已有事件信息 |
| 详细描述 | 选填 | 容纳较长文字，可包含任务说明、网址等；查看时可复制文字 |
| 截图附件 | 选填 | 从相册选择或粘贴多张图片，保存后可在详情中逐张查看；不识别图片内容 |
| 速通时间 | 选填 | 最少完成耗时；建议以小时、分钟输入正时长，空值表示不启用，0 或负值提示纠正 |
| 自定义字段 | 选填 | 每个事件独立的多组字段名与文本内容，可编辑、复制；不提供类型系统或复用模板 |

### 6.2 时间紧急度与统计

令 `r = 截止时间 - 当前时间`，`s = 速通时间`，`u = 普通紧急阈值`。`u` 默认 24 小时，可在设置中调整；未填写 `s` 不使用危险期规则。下面的紧急度用于未完成、未归档、未删除的事项，重要程度不改变计算结果。

| 分类 | 判定与表现 | 确认情况 |
| --- | --- | --- |
| 危险期 | 已填写 `s`，且 `0 < r <= s`；红色并突出感叹号 | 已确认；即使 `s > u`，危险期仍优先 |
| 普通紧急 | 不在危险期，且 `0 < r <= u`；橙色 | 已确认；修改 `u` 不改变临近通知提前量 |
| 普通 | 不满足前两项，且 `r > 0`；使用普通卡片样式 | 从已确认规则得出；具体普通配色待界面审核 |
| 过期 | 建议以 `r <= 0` 判定；默认灰显并保留 | 过期处理已确认；恰好截止时刻算过期是待审默认 |

例如：事项截止于北京时间 18:00，速通时间 2 小时，则 16:00 恰好进入危险期；15:59 尚未进入危险期，普通阈值为 24 小时时显示橙色；18:00 按待审默认转为过期。没有速通时间的同截止事件不会进入危险期。设置重要程度为“高”不改变上述时间分类。

“今日”按北京时间当天日期划分。今日与危险期计数均排除已完成、归档和删除事项，点击后展示同一统计范围。今日已过截止事项是否仍计入，采用第 6.4 节的待审默认。日历查看的是所选日期，不改变“今日”的含义。

### 6.3 完成、归档与删除

| 操作或情况 | 已确认行为 |
| --- | --- |
| 标记完成 | 停止提醒，进入历史列表，退出首页默认待办列表和计数 |
| 恢复未完成 | 重新成为未完成事项；时间紧急度按当前时间计算，不把截止时间自动延后 |
| 过期但未完成 | 不自动视为完成；默认保留、灰显并弱化展示 |
| 归档／一键清理 | 归档保留信息并可在归档列表查看，停止通知，不计首页数量；一键清理过期事项默认归档 |
| 恢复归档 | 可以恢复，按当时的截止时间重新计算时间状态，不自动延后截止时间 |
| 永久删除 | 单项或批量删除均需要明确确认；取消确认保留原数据 |
| 批量管理 | 支持对选中事项完成、归档和删除，不影响未选事项 |

时间是否过期、用户是否完成、是否归档是不同业务维度，不在需求阶段强行规定为互斥的数据库状态。完成与归档组合的默认细节见下一节。

### 6.4 默认行为与审核状态

以下为补全使用流程的默认建议，尚待整体审核。其中多标签及筛选条件的组合方式已由付泽文专项确认，见第 6.5 节；其余建议不因本次局部确认自动获批。

| 主题 | 建议默认行为 |
| --- | --- |
| 状态组合与恢复 | 已完成事项归档或恢复归档时保留原完成标记；只有未完成、未归档且尚未过期的事项重新安排截止前提醒 |
| 过期配置 | 提供“保留并灰显”（默认）与“自动归档”两种处理方式；自动处理不永久删除；一键清理处理过期且未归档事项 |
| 今日与每日汇总 | 统计与汇总包含今天截止但已过期的未完成事项，并标注逾期；不混入往日逾期事项；没有当天事项时不发送空汇总 |
| 通知点击 | 每日汇总进入今日列表；单项提醒进入对应详情；事项已删除时进入列表并说明该事项已不存在 |
| 通知去重与重排 | 同一事项同一截止时间的同类提醒只发一次；危险期与临近提醒同刻触发时合并一条并显示两种原因；编辑或全局设置变化后重排后续提醒，完成、归档、删除后取消后续提醒 |
| 新建或恢复时已临近 | 尚未过期但已处于危险期或临近通知范围时立即提醒一次，同时命中则合并；已经过期的不补发两类截止前提醒；普通列表刷新不重复提醒 |
| 搜索与筛选 | 付泽文已确认多标签全部匹配及不同筛选条件取交集；建议搜索标题、描述和自定义文本名称／内容，默认按截止时间升序；过期项弱化展示，历史及归档保留独立入口，具体待审边界见第 6.5 节 |

这些规则要求卡片、列表、统计与通知一致。权限、应用关闭和设备重启等实际运行条件留待后续技术验证，不以本节承诺任何条件下精确到达。

### 6.5 数据与信息组织专项细化

付泽文于 2026-10-30 开始 FR-14、FR-18、FR-19 的需求工作，确认以下选项：

2026-10-31 付泽文进一步确认：搜索不区分英文大小写、按输入的完整连续文字匹配且多词不自动拆分；相同截止时间按内部标识稳定排序；停用来源或标签仍可用于筛选历史事项。上述局部确认不代表其他默认行为或完整项目需求已获批准。
