## 2. 范围、环境与执行规则

范围涵盖本版全部 FR-01—FR-20、NFR-01—NFR-07。优先检查数据保留、时间边界、完成／归档、通知有效性及图片导入；不扩展到账户、云同步、OCR、多角色或所有 Android 机型兼容。

| 方面 | 计划安排 |
| --- | --- |
| 验收实机 | 荣耀 X50 已由用户确认；实际 MagicOS、Android/API 版本、内存和可用存储在 RUN 批次中登记，不按出厂参数推断 |
| 软件环境 | 记录代码提交号、构建标识、需求／设计版本；具体依赖版本以实际构建为准 |
| 规则测试 | 在开发机使用可替换时钟检查时间、状态、筛选及调度计算；固定测试日期为北京时间 2030-01-02，仅为测试数据 |
| 集成与设备检查 | 验证本地数据库、附件、页面和系统接口；通知、锁屏、后台、重启、图片粘贴至少在荣耀 X50 实测，模拟器结果不能替代验收实机结果 |
| 权限与时间 | 分别登记通知权限、精确闹钟访问、电池优化／后台限制、设备时区；业务时间固定为 Asia/Shanghai |
| 优先级 | P0：数据和核心提醒流程；P1：主要交互与配置；P2：表现细节。优先级用于排序，不表示已确认功能可以不测 |

Android 的“本地测试／设备测试”按运行位置划分，与“单元／集成／端到端”按测试范围划分不同。本项目据此安排纯规则测试和实机检查，参考 [Android 测试基础](https://developer.android.com/training/testing/fundamentals)；权限、恢复与通知场景参考[核心应用质量指南](https://developer.android.com/docs/quality-guidelines/core-app-quality)，不把其全部平台要求扩成课程任务。

- **进入条件**：对应功能可构建、可部署；测试数据与预期已明确；保存被测版本及环境。通知用例还需事先约定允许的到达偏差及运行条件，未约定时只能记录观察，不能直接判为通过。
- **结束条件（建议，待审核）**：P0 全部通过，无影响核心流程的数据丢失或阻断缺陷；其余已确认范围均有执行证据，未测项和遗留问题逐项说明并由项目审核者决定是否接受。完成测试计划不等于完成验收。
- **待审预期**：下文的“[待审]”来自需求第 6.1、6.2、6.4 节或质量建议，确认后才能作为最终通过标准；未确认而尝试执行时标为阻塞，并保留实际观察。
- **记录方式**：一个用例包含多个子场景时，使用 `TC-编号/子场景名` 分别记录，全部适用子场景满足预期才算该用例通过。失败、阻塞、未执行不得被其他子场景的成功覆盖。
- **数据准备**：使用示例任务和图片；每个用例独立重置数据。实机通知采用未来数分钟的任务进行验证，记录真实计划时间和到达时间；固定时钟测试不能冒充系统通知实测。
