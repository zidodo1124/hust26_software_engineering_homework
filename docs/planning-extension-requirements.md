## 2. 功能需求与建议规则

### PX-01 月视图

2026-11-02 付泽文补充：月、周、日视图放在独立日历页面，可从底部直接切换；月历日期格显示事项标题，不同状态使用不同背景色。页面样式整体优化另行处理。

1. 提供可切换上月、下月及回到今天的月历，按北京时间展示；在每个日期格显示当日截止事项的数量或标记，空间允许时显示有限条标题，超出时明确提示还有更多。
2. 点击日期显示当日事项及截止时间、重要程度、完成状态；点击事项进入现有详情。空日期应展示无事项状态。支持遵循当前来源、标签、关键词和列表状态筛选，并在界面说明筛选已生效。
3. 建议月视图默认显示未完成且未归档的事项；已完成／归档是否可单独切换、颜色映射与小屏显示方式待审核。已有“今日 DDL”统计范围不随选中日期或月视图筛选改变。

### PX-02 周、日等其他视图

2026-11-02 付泽文调整：周、日视图参照课表，按时段显示事项；日历开始时刻按“截止时间 − 速通时间”计算，未填速通时间时日历展示按 60 分钟计算。该默认值用于日历展示，不写回事项或改变未填速通时间的危险期及提醒规则；跨日事项在各日期的时间轴展示相应片段。

1. 建议提供月／周／日视图切换、前后周期导航和回到今天，并保持筛选条件；周以周一至周日为建议默认。
2. 周视图按日期展示一周内的截止事项；日视图按截止时间展示当天事项，点击进入详情。无事项时提供空状态。
3. 时段计算以上述 2026-11-02 的新答复为准，取代此前“仅标记截止时刻”的建议；不承诺拖拽排程。年视图、多周视图、订阅日历和拖拽安排均为后续可选项。

### PX-03 重复任务

2026-11-02 付泽文明确：重复任务不需要支持图片附件；其他事项的图片功能继续保留。

1. 新建或编辑事项可选择不重复、每天、每周、每月；按结束日期或次数结束，亦可选择无结束日期。周期按北京时间计算；旧事项默认不重复，原数据保留。
2. 每个周期的完成状态应独立；完成本次不代表全部完成。用户可查看本次与后续周期，并跳过某一次。未完成的过往周期不因到达新周期自动消失或变为完成。
3. 修改／删除时应明确选择“仅本次”或“本次及后续”；确认删除前不得改变数据。仅本次调整不影响其他周期；系列更改保留已完成历史。归档、恢复、筛选与统计应明确区分单次和系列，不重复计数。
4. 建议每月以原始日号为锚：某月无该日时取当月最后一天，下个月仍以原日号计算。例如 1 月 31 日后依次为 2 月末、3 月 31 日。结束日期建议包含当天，次数包含首次；具体规则待团队确认。
5. 不应无限生成或持久化未来实例；实现方案需保证近未来视图可用、重启不重复生成、提醒不重复安排。系列变化后应取消失效提醒并为有效实例重排；通知权限或系统限制不改变任务数据。

### PX-04 子任务／检查清单

1. 每个事项可添加、编辑、删除、排序和逐条勾选检查项；标题去除首尾空白后不可为空，允许多个检查项同名。各项的状态单独保存，退出重开后保留。
2. 详情显示“已完成数／总数”；没有检查项时显示空状态，避免显示无意义的百分比。未保存或保存失败时保留用户草稿并提示。
3. 建议勾完所有检查项不自动完成父事项，完成父事项也不自动修改检查项；父事项恢复后原检查项状态保留。删除父事项时同时删除所属检查项；归档／恢复保留它们。
4. 重复事项建议每个周期拥有独立检查状态，新增周期从系列的检查项模板初始化为未完成；修改本次不改变其他周期。系列模板更新对已有实例的作用范围须在设计审核时明确。

### PX-05 单事项提醒设置

1. 保留现有全局每日汇总、危险期和临近截止提醒及各开关；建议每个事项可选择沿用全局默认、关闭该事项提醒或自定义多个提前量，例如提前 1 天、1 小时。
2. 提醒按该次截止时刻及北京时间计算；设置相同提前量应去重。同一事项、同一时刻若命中多类提醒，沿用合并通知的方向并保留可识别的原因；不同事项不得错误合并成单项提醒。
3. 更改截止时间、提醒配置、完成、归档或删除时，应取消失效计划并重排仍有效的计划；恢复未完成或恢复归档时重新计算。建议过去的提醒不逐条补发；新建或恢复时已进入提醒范围的行为与现有规则的衔接待确认。
4. 界面应显示通知权限及精确提醒能力不可用的状态，并允许前往系统设置；保存事项与通知安排结果应分别提示。通知受权限、系统省电及后台限制影响，不承诺任何条件下准时送达。
5. 重复事项的每次实例独立安排有效提醒；跳过或完成本次应取消本次提醒，不取消后续有效实例。具体自定义提醒数量上限待设计与测试确定，不预设已确认上限。

### PX-06 重要程度排序

1. 待办列表可切换“截止时间优先”和“重要程度优先”。重要程度优先建议高、中、低排序，同级按截止时间升序，再按内部标识稳定排序。
2. 排序只改变显示顺序，不改变重要程度、时间紧急度或已有事项；搜索、来源、标签、日期筛选仍按交集生效。已有逾期事项单独灰显的规则应保留；具体逾期分组内是否应用上述排序待审核。
3. 建议保存用户选择，重新打开后保持；排序适用于哪些历史／归档列表，以及是否提供升降序选项待确认。

### PX-07 统计与复盘

1. 提供本周、本月及自选日期范围的复盘入口，以北京时间自然日划分；展示期间完成数量、期间截止的事项数量，以及其中按截止时间判定的逾期未完成数量。
2. 建议“期间完成”按实际完成时间统计；“期间截止”按截止时间统计；“逾期未完成”指统计时刻已过截止且当前仍未完成的事项。各指标分母与时间口径不同，应在界面标注，不直接混为完成率。
3. 删除的事项不纳入当前统计；归档但未删除的事项是否纳入复盘待团队确认。恢复未完成会影响基于当前状态的统计；不承诺保存每次状态变化或历史快照。重复任务以各周期实例计数，避免系列与实例重复计算。
4. 展示简单的按日完成数量趋势与可访问的文字数值；无数据时给出空状态，避免除零。支持点击数量或日期查看对应事项列表；现有首页今日和危险期统计语义保持不变。

## 4. 依赖、风险与下一步

- 日历、统计与重复任务共用时间和状态规则；先核查现有 Room schema、查询、通知计划及迁移路径，再确定实例模型和有限展开策略，避免旧数据丢失、重复生成和重复通知。
- 检查项与重复系列的复制、编辑范围必须统一；统计口径须在实现前明确，特别是归档、删除、恢复、历史修改和重复实例。
- 单事项提醒需与队友负责的提醒模块协调；本稿不自动重新分配成员工作，也不把需求草案当作实现授权或测试通过。
- 建议迭代顺序：团队审核需求和范围 → 架构及数据迁移核查 → 实现与自动测试 → 更新设计与测试报告 → 最后进行实机验证及演示。七项规模较大，建议团队按课程剩余时间确定最小交付范围；具体顺序和完成日期尚未确定。

## 5. 待团队决定的问题

1. 周／日视图是否同时纳入课程交付，年视图是否留作后续？月格只显示数量还是同时显示标题？

4. 事项级提醒是否覆盖全局提醒，重复与同刻提醒如何合并，已进入提醒范围时如何处理？
5. 归档事项是否进入复盘，逾期与完成率如何定义？排序设置是否跨待办、已完成、归档列表共享？
