## 协作方式

1. 领取时在本人文件更新状态、实际开始时间和本轮交付范围。
2. 从最新 `main` 建自己的功能分支；建议命名 `feature/成员拼音-功能`，完成一项可审查的变化后提交。
3. 提交说明写明功能或修复，PR／审核说明附运行命令、结果、未验证内容和必要截图。不要提交 SDK、缓存、机器路径或私人测试数据。
4. 接口和数据库变更先写明字段、默认值、兼容与迁移方式；关联改动由支盟渊协调合入。
5. 测试发现问题填写[执行与缺陷记录](../docs/test-records.md)，修复后新增复测结果，保留原失败记录。
6. 在[交互记录](../interaction-records/README.md)的本人目录登记真实参与。使用自己的 Git 身份提交实际工作，不代写其他人的贡献或审核。

## 领取与交付记录格式

在本人文件末尾追加：日期时间及所在时区、当前状态、实际完成内容、提交／PR、测试命令及证据、阻塞事项、复核人及意见。可用状态：待领取、进行中、待审核、需修改、已验收。
